# 운영 가이드

## 1. 매달 하는 일

1. 25일에 구글 시트 원본 탭을 평소처럼 정리한다. (정산 기준: 매월 26일 ~ 익월 25일)
2. 특이사항이 있으면 사유를 적는다.
   - 수익·비용 → `요약(재무제표)` 탭 오른쪽 P~AA 열 (해당 월 칸)
   - 자산·부채 → `변동사유(자산)` 탭
3. `포트폴리오상세` 탭의 수량·평단가가 바뀌었으면 고친다. (시세·환율은 자동)
4. 끝. **다음날 아침 6시에 대시보드가 자동으로 갱신된다.**
   바로 보고 싶으면 GitHub → Actions → `대시보드 갱신` → **Run workflow**.

> 구글 시트를 다시 "웹에 게시"할 필요는 **없다.** 게시 주소는 한 번 만들면 계속 유효하고
> 내용만 따라 바뀐다. 새 탭을 대시보드에 쓰려고 할 때만 그 탭을 추가로 게시한다.

## 2. 연말에 하는 일

- `로드맵` 탭 "4) 실제 달성현황"(50–60행)에 그 해 12월 실적을 기록한다.
  올해 행은 대시보드가 실시간 값으로 보여주므로, 연말 확정값만 옮겨 적으면 된다.
- 해가 바뀌면 새 시트(`2027_자산가계부`)를 만들고, `대시보드데이터`·`변동사유(자산)`·
  `포트폴리오상세` 탭을 복사해 넣은 뒤 새로 "웹에 게시"하고 `SHEET_CSV_URL`,
  `SHEET_DETAIL_CSV_URL` 시크릿을 갱신한다.
  제목·연도는 `자산관리!B1`("2027 자산관리")에서 자동으로 읽으므로 코드 수정은 필요 없다.

## 3. 배포

```bash
git add -A && git commit -m "무엇을 바꿨는지" && git push
```

푸시하면 워크플로가 자동으로 돈다(`update.yml`의 `push: branches:[main]`).
코드 변경 없이 데이터만 다시 읽으려면 Actions에서 Run workflow.

### GitHub Secrets

저장소 → Settings → Secrets and variables → Actions

| 이름 | 값 |
|---|---|
| `SHEET_CSV_URL` | `대시보드데이터` 탭 게시 CSV 주소 |
| `SHEET_DETAIL_CSV_URL` | `지출가계부` 탭 게시 CSV 주소 (없으면 상세 내역 기능만 꺼짐) |
| `DASH_PASSWORD` | 대시보드 비밀번호 |
| `NAME_MAP` | 실명→가명 치환표. `실명1=꿀꿀,실명2=말벌,실명3=째니` 형식 |

시크릿을 바꾼 뒤에는 **Run workflow를 한 번 돌려야** 반영된다.

> `NAME_MAP`을 시크릿으로 빼둔 이유: 저장소가 공개라서 코드에 실명을 적으면 노출된다.
> 시크릿이 없으면 치환 없이 진행되는데, 그래도 데이터는 암호화되므로
> 비밀번호를 아는 사람에게만 보인다.

## 4. 보안 전제

- 사이트에 올라가는 것은 **암호화된 `data.enc`뿐**이다. 시트 주소는 사이트에 없다.
- 저장소는 공개지만 시트 주소·비밀번호·실명은 전부 시크릿과 `LOCAL.md`에 있다.
- `robots.txt`와 `noindex`로 검색 노출을 막는다.
- 비밀번호는 브라우저에 저장하지 않는다. 화면을 열 때마다 입력한다.

# 트러블슈팅

## `#REF!` — 특정 월 숫자가 실제보다 작게 나올 때

### 증상
대시보드 상단에 빨간 경고 박스가 뜨고, 그 달의 합계·순자산·달성률이 실제보다 작다.
경고 박스가 어느 블록의 어느 항목·어느 달인지 이름으로 알려준다.

### 원인
`대시보드데이터` 탭은 원본 탭을 **직접 셀 주소로** 참조한다.
원본 탭에서 셀을 잘라내거나 "셀 삭제(밀어내기)"를 하면 그 셀을 가리키던 수식이 전부 `#REF!`가 된다.
값을 지울 때는 `Delete` 키(내용만 삭제)를 써야 한다.

### 복구
1. 경고 박스가 알려준 블록·항목·달을 `docs/sheet-spec.md`의 표에서 찾아 **정확한 셀 주소**를 구한다.
2. 블록별로 방법이 다르다.
   - `#자산`, `#손익`, `#사유` → 같은 행의 **옆 칸을 오른쪽으로 끌어 복사**하면 복구된다.
   - `#월별지표` → 행이 월이라 끌어 복사가 통하지 않는다. 수식을 직접 쓴다.
   - `#로드맵` → 대개 `#월별지표`가 고쳐지면 같이 낫는다.
3. 원본 탭의 값 자체는 대개 멀쩡하다. 수식만 다시 이어주면 된다.

### 값 검산 (원본 값이 맞는지 확인할 때)
- 투자자산 = `요약(재무제표)!E4` 와 일치해야 한다.
- 총자산 = 개별 자산 항목의 합 = `자산관리!{월}38`
- 순자산 = 총자산 − 총부채

### 기록: 2026-09 사례
`대시보드데이터!N16`(국내주식·말벌·9월)과 `G120`(월별지표·9월·투자자산) 두 칸이 `#REF!`가 됨.
원본 `자산관리!N25`의 값은 정상이었고 참조만 끊어진 상태.
→ 두 칸의 수식을 다시 넣어 복구. 오류 칸이 0으로 처리되던 탓에 투자자산·순자산이
그 금액만큼 작게 나왔고, 로드맵 달성률은 표시되지 않다가 복구 후 정상 표시됨.
이 사례 이후 대시보드에 오류 경고 박스를 추가했다.

## 그 밖

| 증상 | 확인 |
|---|---|
| "데이터를 불러오지 못했습니다" | Actions 로그. 대개 `SHEET_CSV_URL` 오타이거나 게시가 중지됨 |
| 비밀번호가 안 먹음 | `DASH_PASSWORD`를 바꾼 뒤 Run workflow를 돌렸는지 |
| 항목을 눌러도 내역이 안 나옴 | `SHEET_DETAIL_CSV_URL` 시크릿이 있는지. 자동이체 항목은 원래 개별 기록이 없어 안 나온다 |
| 404 | Settings → Pages → Source가 `GitHub Actions`인지 |
| 포트폴리오 수익률이 이상함 | `포트폴리오상세` 탭의 수량·평단가 입력, 그리고 티커가 맞는지. GOOGLEFINANCE가 못 읽는 상품은 티커를 비우고 평가금액을 직접 넣는다 |
| 10~12월이 0으로 보임 | 정상. 아직 데이터가 없는 달이다. 기준월 드롭다운에도 안 나온다 |
